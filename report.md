Лабораторна 2. Перша сторінка

Таблиця запитів (DevTools -> Network)

| Запит (Name) | Метод | Статус | Тип | Розмір |
|---|---|---|---|---|
| index.html | GET | 200 | document | ~2.1 kB (разом зі скриптом Live Server) |
| logo.png | GET | 200 | png | ~2 kB |
| ws | GET | 101 | websocket | 0 B |
| logo1.png (навмисна помилка) | GET | 404 | text/html | ~0.2 kB |

Заголовки запиту index.html (Headers): Request URL: http://127.0.0.1:5500/index.html, Request Method: GET, Status Code: 200 OK, Content-Type: text/html; charset=UTF-8.

Помилка 404: коли в src написав images/logo1.png, у Network з'явився червоний запит logo1.png зі статусом 404 Not Found, а на сторінці замість картинки показався текст з alt «Логотип TaskBoard». Після виправлення шляху статус знову 200.

Elements: заголовок у вкладці Elements змінився на сторінці, але файл index.html не змінився. Після F5 повернувся старий текст.

Console: document.title повернула рядок "TaskBoard" (вміст тегу title). Команда document.body.style.background = "lightyellow" зробила фон сторінки світло-жовтим. Після F5 фон знову білий, бо зміна була лише в пам'яті браузера.

Відповіді на запитання

1. Яка адреса сторінки в браузері? З яких частин вона складається?
Адреса http://127.0.0.1:5500/index.html. Тут http — протокол, 127.0.0.1 — адреса хоста (мій власний комп'ютер, localhost), 5500 — порт, на якому працює Live Server, а /index.html — шлях до файлу на сервері.

2. Скільки запитів зробив браузер при завантаженні сторінки і чому саме стільки?
Браузер зробив 3 запити: index.html, logo.png і WebSocket-з'єднання ws. Спочатку завантажується HTML-документ, потім браузер знаходить у ньому тег img і окремо запитує картинку, а ws відкриває скрипт Live Server для автооновлення сторінки.

3. Що відбулось, коли ти поставив неправильний шлях до зображення?
Сервер не знайшов файл logo1.png і повернув статус 404 Not Found. Картинка не показалась, замість неї браузер вивів текст з атрибута alt.

4. Чому зміни, зроблені через DevTools, зникли після F5?
DevTools змінює лише DOM-дерево, яке браузер зберігає в пам'яті, а не сам файл на диску. Після F5 браузер знову запитує index.html у сервера й будує сторінку з оригінального файлу.

5. Хто в цій схемі клієнт, а хто сервер?
Клієнт — це браузер, який надсилає HTTP-запити. Сервер — Live Server, запущений на моєму комп'ютері (127.0.0.1:5500), який віддає файли проєкту у відповідь.
